# Data model and movement

`event_questions` stores ordered organizer-defined text questions and required flags. Drafts may have missing required answers; direct submissions, draft submission, and edits of submitted projects validate all required answers on the server. Question definitions lock after the first submission or the submission deadline. `judge_track_scopes` stores nullable event-wide or explicit track lists, and `role_invite_scopes` preserves restrictions until an invited judge accepts.

`users` owns login identities; `sessions` stores hashed, expiring tokens. `events` has dates and state. `event_roles` scopes participant, judge, and organizer roles to one event; `users.is_admin` is platform-wide. `tracks` and `prizes` belong to events.

`teams` has a creator, `team_members` has unique membership per team, and `team_invites` contains hashed expiring links with use counts. `role_invites` binds an expiring single-use link to an email, event, and role. The API also prevents one user joining two teams in the same event and caps teams at four people.

`projects` has a team, track, draft/submitted status, source fixture ID, and optional duplicate reference. `project_details` holds longer descriptions, media URLs, tech tags, and optional custom answers. `rubrics` are versioned; `criteria` stores score bounds and weights. `assignments` is separate from `reviews`, making pending work explicit. Each review records the rubric version, and `criterion_scores` stores the individual values. `result_snapshots` holds published scores. `votes` enforces one ballot per user and event; `comments` stores public or hidden project discussion; `audit_events` traces vote, comment, moderation, and blocked abuse actions. Public vote totals are computed from `votes` after publication rather than stored in the judging snapshot.

`webhooks` stores organizer endpoints and signing secrets, and `webhook_deliveries` stores attempt state and errors. `signing_keys` stores the active server HMAC key; `issued_records` stores signed project and judge participation payloads. Neither signing keys nor webhook secrets are present in the JSON event export.

On first start, the importer reads `fixtures.json` into the local database. The fixture's 40 teams, 41 project rows, 30 judge accounts, and completed scores retain their published IDs. The original closed submission deadline is preserved. The importer adds pending assignments to projects with fewer than three assignments; these have no review score and are counted as pending. Separate stable IDs seed the open submission, pending review, and community voting demos. The organizer CSV export at `/api/events/{id}/export.csv` contains project IDs, titles, track IDs, duplicate flags, review counts, raw scores, adjusted scores, and method. CSV cells beginning with spreadsheet formula characters are prefixed for safe opening. `/api/events/{id}/export.json` exports the complete event data without secrets. `/api/events/{id}/import.json` imports tracks, prizes, teams, projects, details, and matching existing team-member accounts into an unpublished event atomically; it does not restore reviews, votes, comments, or role memberships.
