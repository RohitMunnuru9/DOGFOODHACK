# Judging and normalization

Batch assignment fills each submitted, nonduplicate project to an organizer-selected review count (1–10). It selects eligible judges with the fewest existing event assignments, breaking ties by stable user ID. Track scopes, team conflicts, and existing assignments are enforced. Repeating a batch only fills gaps and cannot create duplicate assignments. Insufficient eligible judges produce visible per-project shortfalls rather than relaxing isolation. Progress includes every event judge, including those with zero assignments. Manual assignment remains available for organizer adjustments.

An organizer invites a judge by email-specific link and manually assigns a submitted project. Judge grants and invitations accept `track_ids`: null means event-wide permission, a list restricts the judge to those event tracks, and an empty list grants no judging tracks. The fixture judges retain their published track scopes. The server checks the event role, track scope, and team conflict on assignment, and rechecks the current scope when reading or saving a review. Changing a scope cannot expose or edit an old assignment outside the new scope. The public project gallery remains public. Each review uses the active rubric when first saved; later rubric changes do not alter that review's criteria. Scores must include every criterion at submission, stay within its configured 1–5 range, and are stored unchanged.

For each submitted review, compute its raw score as `sum(weight_i × value_i) / sum(weight_i)`. In each track, compute the mean raw review score `M`. For judge `j`, compute their track mean `M_j` and number of reviews `n_j`. The severity correction is `(n_j / (n_j + 4)) × (M_j − M)`. The adjusted review is `clamp(raw − correction, 1, 5)`. A project's raw and adjusted scores are the mean of its completed review scores. Missing and draft reviews contribute no score. Projects are ranked within tracks. The method identifier is `judge-mean-shrinkage-v1`.

The four-review shrinkage constant limits the influence of judges with few reviews. An additive correction avoids division by zero for judges who always give the same score. This method does **not** fully separate judge severity from project quality when assignment groups have different quality distributions. A connected-overlap estimator would improve this. The fixture duplicate is flagged and excluded from the score input; its row remains in the export with no adjusted score. Raw scores, review ownership, pending counts, and rubric versions remain inspectable for an organizer. Public results are unavailable until publication; publication stores a snapshot rather than recalculating on every read.
